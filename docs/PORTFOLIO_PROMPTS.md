# Prompts for maintaining this portfolio

[Profile](../README.md) · [Project index](../projects/INDEX.md)

These prompts are tailored to this portfolio. They synthesize GitHub's official guidance and themes from Reddit discussions; they are not quotations or guaranteed hiring formulas.

## Audit a project before describing it

```text
Inspect this repository's instructions, source, package scripts, tests, README,
and existing project evidence before editing. Identify the actual problem,
implemented features, my documented contribution, team attribution, and
current limitations. Separate original work, later improvements, reconstructed
demos, simulations, and future plans. Do not invent users, metrics, deployment,
clinical validation, awards, or test results. Propose a concise README using
verified file paths and runnable commands. Flag contradictions instead of
quietly choosing the most impressive claim.
```

## Improve the profile and project navigation

```text
Review my profile README and project index for an engineering/product internship.
Make the introduction clear in two sentences and feature 3–5 relevant projects.
For each, explain the problem, my contribution, status, and a verified route to
code or a demo. Keep the full project catalog one click away. Preserve useful
photos, contribution credits, and evidence. Use restrained typography and
accessible alt text. Keep private repositories private and never copy private
source or credentials into the public profile. Check local links after edits.
```

## Prepare a project for an interview

```text
Use this project's actual source and documented history to prepare a two-minute
walkthrough: problem, my role, architecture, one important tradeoff, one failure
case, validation performed, and next step. Give me five technical follow-up
questions. Clearly distinguish what I implemented, what teammates implemented,
and what AI-assisted tools helped generate. Do not answer questions with claims
that are absent from the evidence.
```
